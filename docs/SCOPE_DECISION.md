## 15. 需要你确认的 3 个分歧点

### 分歧 1：F6 密码恢复入口 —— 建议删

现状 `GET/POST /admin/set-password` **无任何认证**。虽然有"`meta.admin_password` 非空时 302"的护栏，但它是一个绕过认证的写入口。

**建议**：删除。改用「OOBE 首启设置密码」+「管理员登录后改密」两条路。
**如果保留**：必须加"一次性 token + 短时效"。

### 分歧 2：D5 飞书 fail-open —— 建议改

现状：没配 `FEISHU_VERIFICATION_TOKEN` / `ENCRYPT_KEY` 时**跳过所有校验**。
**建议**：默认 fail-closed（无凭据则拒绝），开发环境用显式开关 `FEISHU_DEV_ALLOW_UNSIGNED=1`。

### 分歧 3：J1 调度方式 —— 需要你选

| 方案 | 优点 | 缺点 |
|---|---|---|
| **保留 host cron** | 改动最小；日志/调试直观 | 裸机路径需要用户配 cron；Docker 路径需挂载宿主 crontab（别扭） |
| **容器内调度（APScheduler）** | Docker 路径自包含，一个容器搞定 | 多一个依赖；容器重启需处理"错过的任务"；与现有双 cron + flock 设计不兼容 |
