# Round 63 — added bcrypt for session-auth password hashing.
#   auth.py stores users.password_hash as bcrypt(str, gensalt(rounds=12))
#   so a stolen DB leak does not reveal plaintext passwords.  Rounds=12
#   trades ~250 ms / hash on a typical server against a major slowdown
#   of offline brute-force.  The dashboard only hashes on login /
#   admin-creation events (not per request), so the latency is bounded
#   to the user-facing auth path.
#
#   Pre-R63 the project used HTTP Basic Auth against meta.admin_password
#   (plain text) which was acceptable for a single-tenant home dashboard
#   but blocked adding / removing users without touching SQL.  bcrypt
#   unlocks the per-user + session-revoke model that R63 introduces.
# Round 34D — dropped beautifulsoup4 (Round 21 L3 dead-dep audit).
#   The scraper parses portal responses with stdlib ``html.parser`` via
#   ``BeautifulSoup(..., 'html.parser')`` only when BS4 was present,
#   but every code path was migrated to regex / lxml-free parsing in
#   Round 21.  No code anywhere in the repo still imports bs4; verify
#   with:  grep -r "from bs4\|import bs4" dorm-power-monitor/
#
# Round 61 — added pydantic as a top-level dependency.
#   The data layer was split into db.models (Pydantic v2 entities:
#   Record / DailyElec / Violation / Pay / RunStatus / MetaEntry /
#   StatsCard) and db.repo (Repository wrappers around the same
#   SQL).  Pydantic v2 is the project-wide pin (>=2.0,<3.0) — the v1
#   API is intentionally NOT supported because db.models uses
#   Pydantic v2-only features (ConfigDict, field_validator, alias
#   semantics).  Pre-R61 callers keep working unchanged: the db
#   package re-exports every legacy public function from
#   db._legacy.py, so ``import db; db.insert(...)`` still works
#   without pydantic installed (the legacy code path never imports
#   it).  pydantic only matters for code that opts into the new
#   typed surface (``from db.models import Record``).
